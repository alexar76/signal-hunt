## 1. Что такое Signal Hunt

Signal Hunt — игра-расследование **и образовательная лаборатория** внутри федерации
AIMarket. Каждый раунд создаётся из реального снимка обычного Hub: внешних
capabilities, распределения по источникам, фактических цен, подписанной идентичности и
сохранённой истории. Игрок изучает улики, выбирает диагноз и указывает уверенность.

Это **лабораторный курс в оболочке игры**: петля удерживает внимание, а материал —
живая грамотность федерации: читать телеметрию Hub, платить за улики, калибровать
уверенность через Brier, проверять криптографические коммитменты и видеть, как рост
федерации, join/leave пиров и погода задержек меняют доступные диагнозы.

Это не симулятор с демонстрационными данными. Если Hub невозможно измерить, игра
возвращает состояние недоступности, а не подставляет фикстуру. Отсутствующая история
или цена остаётся отсутствующей.

### Образовательные результаты

После нескольких раундов внимательный игрок должен уметь:

1. Объяснять наблюдение Hub по измеренным источникам, а не по спекуляции.
2. Сознательно менять цену улик на score через опубликованный evidence factor.
3. Заявлять уверенность, которая выдерживает Brier, а не блефовать категоричность.
4. Пересчитать вердикт по соли, коммитменту и возвращённым операндам.
5. Связывать классы детекторов (изоляция, исчезновение, смена реестра пиров, погода задержек,
   концентрация, …) с реальной динамикой каталога, реестра и задержек при росте федерации.

## 2. Что работает на игровом сервере

Production-развёртывание включает PostgreSQL, обычный AIMarket Hub, игровой движок и
Caddy как TLS-вход. Одноразовый bootstrap регистрирует пять локальных capabilities:

| Capability | Назначение |
|---|---|
| `signal.case@v1` | Текущее неизменяемое расследование |
| `signal.evidence@v1` | Раскрытие одной зафиксированной улики |
| `signal.submit@v1` | Проверка диагноза и вычисление очков |
| `signal.leaderboard@v1` | Рейтинг только из сохранённых вердиктов |
| `signal.heroes@v1` | Добровольно публичные подписанные достижения |

Общая случайность и аналитика не копируются внутрь игры. При доступности движок через
свой Hub обнаруживает удалённую `sortes.draw@v1` и сохраняет маршрут, Hub-источник,
receipt nonce и result hash. Сбой записывается как `unavailable` и не выдаётся за вызов.

## 3. Путь игрока

1. **Наблюдение.** Первый экран показывает измеренный Hub, источники, количества
   capabilities, задержку manifest, ID наблюдения и state hash.
2. **Исследование.** Доступны шесть улик: распределение, изменение во времени, цены,
   реестр пиров, поверхность задержек и происхождение (provenance).
3. **Решение.** Игрок выбирает один из четырёх диагнозов, при желании отвечает на
   follow-up (второй замок) и указывает уверенность 25–100%.
4. **Проверка.** Сервер раскрывает соль, проверяет commitment, добавляет бонус follow-up
   и зафиксированный множитель PRIME, сохраняет вердикт и показывает клиффхэнгер следующего окна.
5. **Прогресс.** Очки определяют статус; дневная серия, недельный паспорт и явные
   предикаты открывают реликвии. Сильные орбиты можно одним нажатием отправить в hero feed
   после opt-in. Ничего не минтится, финансовая ценность не обещается.

Понятные правила вовлечения и формулы — в [полных правилах](RULES.ru.md), §6–7.

## 4. Модель доказательности

Наблюдение хранит время генерации upstream, локальное время измерения, URL и signer key
Hub, количества по источникам, агрегаты цен, статусы запросов и канонический state hash.
Раунд ссылается на этот снимок: более новые данные не меняют уже созданные улики.

Диагноз определяется объявленными детерминированными порогами. До публикации раунда
движок создаёт случайную соль и публикует:

```text
SHA256(round_id:answer_code:answer_salt)
```

Ответ и соль раскрываются только в вердикте. Проверяющий может повторить commitment и
все операции scoring по данным ответа API.

## 5. Идентичность, приватность и герои

По умолчанию игра анонимна. Браузер получает непрозрачный подписанный session token и
хранит его на устройстве. Кошелёк, почта и social login не нужны. Сырые IP-адреса в
игровых таблицах не сохраняются.

Позывной можно изменить. Публичность героев изначально выключена и действует только на
будущие достижения после явного opt-in. Feed содержит позывной, агрегированные
проверенные показатели, коды наград и ссылки на доказательство; session token, IP и
приватные улики в него не входят.

DIOSCURI забирают feed сами и сверяют Ed25519-ключ с закреплённым оператором ключом.
Доставка Discord и X учитывается отдельно: повтор одной платформы не дублирует другую.
Игра никогда не получает токены социальных сетей.

## 7. Локальный запуск

Сначала запустите AIMarket Hub, затем backend и интерфейс:

```bash
cd signal-hunt
python -m venv .venv
.venv/bin/pip install -e '.[dev]'
SIGNAL_HUNT_HUB_URL=http://127.0.0.1:9183 .venv/bin/python -m signal_hunt.main
```

```bash
cd signal-hunt/frontend
npm ci
npm run dev
```

Если настроенный Hub не отдаёт корректный живой manifest, страница намеренно показывает
ошибку вместо демонстрационного раунда.

## 8. Production-развёртывание

1. Направьте DNS A/AAAA на новый сервер; откройте TCP 80/443 и UDP 443.
2. Скопируйте `.env.example` в `.env`.
3. Независимо сгенерируйте `AIMARKET_ADMIN_TOKEN` и `POSTGRES_PASSWORD`.
4. Проверьте seed public keys по отдельному каналу: endpoint не может сам назначить
   себе доверие.
5. Запустите `scripts/deploy.sh`.
6. С доверенной операторской машины выполните `scripts/register-upstream.sh`, чтобы
   существующий Hub сделал announce, approve и crawl нового Hub.
7. Выполните `scripts/verify.sh https://<домен-signal-hunt>`.

Только Caddy публикует порты. Ключи Hub и provider лежат на постоянных томах; их нужно
резервировать вместе с PostgreSQL и игровым состоянием.

## 9. Эксплуатация и состояния отказа

- `503 federation_unavailable` — живой раунд невозможно построить.
- `null` baseline — недостаточно измеренной истории, а не нулевое изменение.
- `federation_assist.status=unavailable` — честная деградация без заявления о VRF.
- Повтор submission возвращает сохранённый вердикт и не создаёт новую награду.
- Потеря signing key меняет идентичность и требует восстановления доверия.
- Ошибка relay видна в `/health` DIOSCURI, но не блокирует игру.

```bash
cd signal-hunt && pytest -q
cd frontend && npm run build
```
