# Signal Hunt — 游戏规则

> 语言：[English](RULES.md) · [Русский](RULES.ru.md) · [Español](RULES.es.md) · [Français](RULES.fr.md) · **中文**
> 完整指南：[中文](GUIDE.zh.md)
> 术语：[本地化术语表](https://github.com/alexar76/aicom/blob/main/docs/localization-glossary.md)（Signal Hunt 章节）

## 1. 目标

识别真实 AIMarket 联邦快照中的状态，表达经过校准的置信度，并获得最高可复现
得分。游戏没有隐藏人工裁判。

Signal Hunt **同时也是教育实验室**：每一回合都是关于联邦遥测、证据成本、概率评分
与密码学承诺的实时实训——不是带 fixtures 的玩具模拟。

## 1.1 教育价值

一回合训练可迁移到 AIMarket / AICOM 技术栈的具体能力：

| 技能 | 实验室强制练习什么 |
|---|---|
| 阅读实时联邦状态 | Manifest、来源、价格、peer 名册、延迟探测、来源 (provenance)——仅测量值 |
| 证据纪律 | 少开证据块保住分数；数据有真实成本 |
| 校准过的置信度 | Brier skill 奖励诚实；过度自信受罚 |
| 密码学核验 | 答案承诺与裁决的独立重算 |
| 检测器素养 | 按声明顺序的命名阈值（隔离、消失、peer 变动、延迟天气、集中……） |
| 联邦动态 | 增长、peer 加入/离开、延迟天气与价格变化改变可用诊断 |
| 诚实的公开证明 | 英雄中继只携带已签名、已验证的轨道 |

请把产品理解为 **游戏 + 实验课**：游戏抓住注意力；可复现数学与实时 Hub 才是课程。

## 2. 回合

- 默认回合窗口为 1,800 秒（30 分钟），可通过 `SIGNAL_HUNT_ROUND_SECONDS` 配置。
- 回合不可变，并绑定规范观测 state hash。
- 每个 session 每回合只能提交一次；重复请求返回已存裁决。
- 公开任务卡保持**封存**：裁决前仅显示 severity（`anomaly` / `calm`）与基线深度；检测器类别随答案一并揭示。
- 展示四个诊断。顺序可使用远程签名 VRF 熵；远程调用不可用时会明确记录。
- 正确答案在玩家行动前已 commitment。

## 3. 检测优先级

以下条件按顺序判断，第一个匹配项获胜：

1. **联邦隔离：** 外部 capabilities 数量为零。
2. **来源消失：** 某个历史中位数至少为 3 的来源现在缺失。
3. **Peer 名册变动：** peers 端点可用且实测名册发生变化——既有 peer（≥2 次历史出现）离开，
   和/或在历史深度 ≥2 时出现新 peer。Capability 来源消失是另一信号，优先级更高。
4. **目录收缩：** 至少减少 3 个，且低于历史中位数至少 15%。
5. **目录扩张：** 至少增加 3 个，且高于历史中位数至少 15%。
6. **价格变化：** 中位价格绝对差至少 `$0.001`，相对差至少 20%。
7. **延迟天气：** 至少一个 peer 的**成功测得**探测 RTT 高于 `500 ms`。失败/跳过的探测
   将 `latency_ms` 记为 `null`，从不捏造天气。
8. **来源集中：** 至少两个来源时，最大来源占外部 capabilities 至少 60%。
9. **稳定：** 未跨越以上任何阈值。

历史不足时，历史条件不能成立；系统不会生成合成 baseline。Peer RTT 通过对 peer 的
`/.well-known/ai-market.json` 探测测得（有上限）。

## 4. 证据

- **来源分布：** 外部总量及各来源数量/占比。
- **历史变化：** 当前总量、历史样本和测量中位数。
- **价格：** 当前价格汇总及可用历史中位数。
- **名册：** 联邦 peers（url、名称、capabilities），相对历史的加入/离开。
- **延迟：** 测得的 peer RTT、阈值（`500 ms`）、偏慢数量。
- **来源证明：** URL、时间、state hash、signer key 和请求状态。

每个首次打开的证据块使系数减少 0.05。六块全部打开时为 0.70（下限）。
重复打开同一块不会再次扣分。

## 5. 置信度

置信度是分配给所选诊断的概率，范围 0.25–1.00。剩余概率平均分给其余三个：

```text
r = (1 − confidence) / (K − 1)，v1 中 K = 4
```

返回的全部概率之和始终为一。

## 6. 得分

```text
Brier = Σ(pᵢ − oᵢ)²
baseline = 1 − 1/K
skill = max(0, 1 − Brier / baseline)
evidence_factor = max(0.70, 1 − 0.05 × opened_evidence)
base_score = round(1000 × skill × evidence_factor)
```

可选**第二道锁**（基于同一测量场的微问题）：

```text
follow_up_bonus = 答对 follow-up 时为 150，否则为 0
combined = base_score + follow_up_bonus
```

**PRIME 窗口：** 每个 UTC 小时的前 15 分钟。在 PRIME 内创建的回合锁定 `×1.5`：

```text
round_score = round(combined × (prime_locked 时为 1.5，否则为 1.0))
```

正确且校准良好的高置信答案得分高。错误但极度自信比谨慎错误惩罚更重。四项均为
25% 的均匀猜测，skill 为零。API 返回全部操作数，任何人都能复算。

## 7. 互动规则（白话说明）

这些机制全部建立在同一套 Hub 测量数据上，不会为了「热闹」虚构内容。

### 7.1 第二道锁（双步操作）

选定诊断后，可再回答一道基于同一观测的可选微问题，例如：

- 哪个来源在场中领先，
- 相对历史，实际价格中位数是升 / 降 / 持平，
- 外部 capability 计数落在哪个区间，
- 当前测得最慢的 peer 是谁（`latency_weather`），
- peer 名册是加入 / 离开 / 两者 / 保持（`peer_churn`）。

允许跳过。第二道锁答对会在 PRIME **之前**给 `base_score` **+150**。
同一回合诊断与 follow-up 均正确可解锁**双锁**。

### 7.2 PRIME 窗口

每个 UTC 小时，分钟 **0–14** 为 PRIME（`×1.5`）。

- 倍率在**回合创建时锁定**。
- 在 PRIME 诞生的回合里稍后提交仍拿 `×1.5`。
- 在 PRIME 外诞生的回合即使在后续热窗口提交也仍是 `×1.0`。

### 7.3 日连续与护盾

按 UTC 日历日游玩会累积**日回归连续**。一枚**护盾**可覆盖恰好一天缺席。
连续活到三天可获得**连续守护者**。界面会显示连续是否仍存活、护盾是否仍可用。

### 7.4 实时在场

回合卡片显示近期有多少 session 活跃，以及有多少人已解出**本**回合。
这些是游戏数据库中的真实聚合，不是虚构人气。

### 7.5 周赛护照

每个 ISO 周有独立护照：

| 目标 | 徽章 |
|---|---|
| 3 个不同正确诊断 | 赛季通才 |
| 3,000 周积分 | 赛季猎手 |
| 3 次 PRIME 窗口正解 | PRIME 跑者 |

进度随新的 ISO 周重置。另有**周排行榜**统计本周积分。

### 7.6 悬念提示

裁决后会提示下一封存场窗口何时开启。这是绑定真实回合 `expires_at` 的提醒，
不是虚构异常的预告片。

### 7.7 Perfect Orbit 广播

得分 ≥ 950 时，在启用公开英雄中继后可一键把结果送入签名英雄 feed。
晚 opt-in 也有效：先私下通关 → 开启中继 → 再广播。因奖励 / 得分 ≥ 900 产生的自动
英雄事件仍见第 11 节。

## 8. 等级星座

| 等级 | 最低累计分 |
|---|---:|
| 观星者 | 0 |
| 探路者 | 500 |
| 信号分析师 | 1,500 |
| 虚空领航员 | 3,500 |
| 星座守护者 | 7,500 |
| 联邦预言机 | 15,000 |

等级仅由持久化累计得分决定，不能购买。

## 9. 遗物与徽章

| 徽章 | 精确条件 |
|---|---|
| 首次接触 | 完成至少一个已验证回合 |
| 校准心智 | 当前裁决 Brier ≤ 0.08 |
| 深度扫描 | 打开六块证据后正确回答 |
| 纯净向量 | 正确回答且回合得分 ≥ 800 |
| 信号直觉 | 正确、无证据、置信度 ≥ 75% |
| 三重锁定 | 最佳连续正确次数达到三 |
| 资深观察者 | 完成至少五个已验证回合 |
| 完美轨道 | 正确回答且回合得分 ≥ 950 |
| 双锁 | 同一回合诊断与 follow-up 均正确 |
| 连续守护者 | 日回归连续达到三（可用一枚护盾填一天空档） |
| 赛季通才 | 当前 ISO 周内 ≥ 3 个不同正确诊断 |
| 赛季猎手 | 当前 ISO 周内周积分 ≥ 3,000 |
| PRIME 跑者 | 当前 ISO 周内 ≥ 3 次 PRIME 窗口正解 |

每枚徽章每个 session 只保存一次。它们只是装饰性记录，不是金钱、token、NFT、
可转让财产或外部价值承诺。

## 10. 排行榜

公开呼号、验证积分、回合数、正确数、名次和等级。排序依次为累计分、正确数、
更低平均 Brier、再按更早的最后游戏时间。不会公开 session token 或私人证据。

另有**周排行榜**汇总当前 ISO 周积分。

## 11. 英雄播报

默认不公开。明确 opt-in 后，未来解锁新奖励**或**得分 ≥ 900 的回合可创建最多一个事件。

启用英雄中继后，也可对 Perfect Orbit / 得分 ≥ 950 进行一键**广播**（含私下强裁决后的
晚 opt-in）。

Feed 对规范 JSON 原始字节使用持久 Ed25519 provider key 签名。DIOSCURI 会拒绝
过期、未来时间、被修改或 key 错误的 feed；Discord 与 X 分别幂等投递。

## 12. 公平游戏

- 不要自动提交或批量创建 session 操纵排行榜。
- 不要使用他人的 session token，也不要把修改后的本地客户端/数据库冒充公网部署。
- 鼓励独立验证、源代码审查和自托管。
- 运营方可过滤自动流量和攻击性呼号，但不得为特定玩家修改持久化裁决数学。

## 13. 独立验证

```text
SHA256(round_id:answer_code:answer_salt) == answer_commitment
```

随后重算概率、Brier、skill、evidence factor、follow-up 加成、PRIME 倍率与四舍五入后的
score。报告不一致时只提供 round ID 与 state hash，绝不要提交 session token。
