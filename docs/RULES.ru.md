# Signal Hunt — правила игры

> Языки: [English](RULES.md) · **Русский** · [Español](RULES.es.md) · [Français](RULES.fr.md) · [中文](RULES.zh.md)
> Полное руководство: [Русский](GUIDE.ru.md)
> Термины: [глоссарий локализации](https://github.com/alexar76/aicom/blob/main/docs/localization-glossary.md) (раздел Signal Hunt)

## 1. Цель

Определить состояние реального снимка федерации AIMarket, правильно выразить
уверенность и получить максимальный воспроизводимый балл. Скрытого судьи нет.

Signal Hunt — это ещё и **образовательная лаборатория**: каждый раунд — живой практикум
по телеметрии федерации, цене улик, вероятностному скорингу и криптографическим
коммитментам, а не игрушечная симуляция с фикстурами.

## 1.1 Образовательная ценность

Раунд тренирует навыки, которые прямо переносятся на стек AIMarket / AICOM:

| Навык | Что заставляет делать лаборатория |
|---|---|
| Чтение живого состояния федерации | Manifest, источники, цены, реестр пиров, пробы задержки, происхождение (provenance) — только измеренное |
| Дисциплина улик | Меньше открытых блоков — выше score; данные имеют цену |
| Калиброванная уверенность | Brier skill поощряет честность; самоуверенность наказывается |
| Криптографическая проверка | Коммитменты ответа и независимый пересчёт вердикта |
| Грамотность детекторов | Именованные пороги (изоляция, исчезновение, смена реестра пиров, погода задержек, концентрация, …) в объявленном порядке |
| Динамика федерации | Рост, join/leave пиров, погода задержек и сдвиги цен меняют доступные диагнозы |
| Честное публичное доказательство | Opt-in hero relay несёт только подписанные орбиты |

Продукт стоит читать как **игру + лабораторный курс**: игра удерживает внимание,
воспроизводимая математика и живой Hub — это учебная программа.

## 2. Раунд

- Стандартное окно раунда — 1 800 секунд (30 минут); оператор может изменить через
  `SIGNAL_HUNT_ROUND_SECONDS`.
- Раунд ключуется по state hash поля, не по часам. Решённый заморожен; несыгранный
  может обновиться, если новые снимки меняют диагноз.
- Одна сессия делает одну попытку. Повтор возвращает сохранённый результат.
- Публичная карточка миссии **запечатана**: до вердикта видны только severity
  (`anomaly` / `calm`) и глубина baseline. Класс детектора раскрывается с ответом.
- Показываются четыре диагноза. Их порядок может использовать подписанную случайность
  удалённого VRF; недоступность такого вызова фиксируется явно.
- Правильный ответ committed до первого действия игрока.

## 3. Приоритет детектора

Побеждает первое выполненное условие в следующем порядке:

1. **Изоляция:** внешних capabilities ровно ноль.
2. **Исчезновение источника:** отсутствует ранее виденный источник с исторической
   медианой не менее трёх capabilities.
3. **Смена реестра пиров:** endpoint пиров доступен и измеренный roster изменился —
   устоявшийся пир (≥2 прошлых снимка) ушёл и/или появился новый пир при глубине
   истории ≥2. Исчезновение capability-источника — другой сигнал и имеет приоритет.
4. **Сокращение каталога:** минимум на три capability и минимум на 15% ниже медианы.
5. **Расширение каталога:** минимум на три capability и минимум на 15% выше медианы.
6. **Сдвиг цены:** абсолютная разница медианы не меньше `$0.001`, относительная — 20%.
7. **Погода задержек:** хотя бы у одного пира **успешно измеренный** probe RTT выше
   `500 ms`. Неудачные/пропущенные пробы хранят `latency_ms = null` и не выдумывают погоду.
8. **Концентрация:** при двух и более источниках крупнейший несёт минимум 60%, **и это
   доминирование новое относительно предыдущего снимка**. Первое наблюдение без истории
   всё ещё может сработать. Устойчивые 60% — это `stable`.
9. **Стабильность:** ни один объявленный порог не пересечён.

Если истории недостаточно, исторический порог не срабатывает. Синтетический baseline не
создаётся. RTT пира измеряется запросом к `/.well-known/ai-market.json` пира во время
наблюдения (с лимитом), а не выводится из crawl-метаданных Hub.

## 4. Улики

- **Распределение:** внешний итог, количество и доля каждого источника.
- **Изменение:** текущий итог, исторические точки и измеренная медиана.
- **Цены:** текущие ценовые агрегаты и исторические медианы при наличии.
- **Реестр:** пиры федерации (url, имя, capabilities), join/leave к истории.
- **Задержки:** измеренные RTT пиров, порог (`500 ms`), число медленных.
- **Происхождение:** URL Hub, времена, state hash, signer key и статусы источников.

Каждый впервые открытый блок уменьшает множитель на 0,05. Шесть блоков дают 0,70
(нижняя граница). Повторное открытие не добавляет штраф.

## 5. Уверенность

Уверенность — вероятность выбранного диагноза. Для четырёх вариантов она лежит от 0,25
до 1,00. Остаток поровну распределяется по трём другим вариантам:

```text
r = (1 − confidence) / (K − 1), где K = 4
```

Сумма возвращённых вероятностей всегда равна единице.

## 6. Очки

Для вероятностей `pᵢ` и one-hot результата `oᵢ`:

```text
Brier = Σ(pᵢ − oᵢ)²
baseline = 1 − 1/K
skill = max(0, 1 − Brier / baseline)
evidence_factor = max(0.70, 1 − 0.05 × opened_evidence)
base_score = round(1000 × skill × evidence_factor)
```

Опциональный **второй замок** (follow-up по тем же измерениям):

```text
follow_up_bonus = 150 при верном follow-up, иначе 0
combined = base_score + follow_up_bonus
```

**Окно PRIME:** первые 15 минут каждого UTC-часа. Раунды, созданные в PRIME,
фиксируют `×1.5`:

```text
round_score = round(combined × (1.5 если prime_locked иначе 1.0))
```

Верный ответ с калиброванной уверенностью получает высокий балл. Ошибочная высокая
уверенность наказывается сильнее осторожной ошибки. Равномерное угадывание 25% имеет
нулевой skill. API возвращает все операнды для независимого пересчёта.

## 7. Правила вовлечения (простыми словами)

Все эти механики опираются на те же измеренные данные Hub. Ничего не выдумывается «для
драйва».

### 7.1 Второй замок (двойной ход)

После выбора диагноза можно ответить на один необязательный микровопрос по тому же
наблюдению, например:

- какой источник лидирует в поле,
- цена выросла / упала / осталась плоской относительно истории,
- в каком диапазоне число внешних capabilities,
- какой измеренный пир сейчас самый медленный (`latency_weather`),
- реестр пиров: пришли / ушли / и то и другое / удержался (`peer_churn`).

Пропуск разрешён. Верный второй замок даёт **+150** к `base_score` **до** PRIME.
Верный диагноз **и** верный follow-up в одном раунде открывают **Двойной замок**.

### 7.2 Окно PRIME

Каждый UTC-час минуты **0–14** — PRIME (`×1.5`).

- Множитель **фиксируется при создании раунда**.
- Поздний submit в PRIME-раунде всё равно получает `×1.5`.
- Раунд, рождённый вне PRIME, остаётся `×1.0`, даже если вы отвечаете уже в горячем окне.

### 7.3 Дневная серия и щит

Игра в календарные UTC-дни строит **дневную серию возвратов**. Один **щит** может
закрыть ровно один пропущенный день. На третьем живом дне доступен **Хранитель серии**.
В интерфейсе видно, жива ли серия и остался ли щит.

### 7.4 Живое присутствие

На карточке раунда — сколько сессий недавно были активны и сколько уже решили **этот**
раунд. Это реальные агрегаты из БД игры, не имитация толпы.

### 7.5 Недельный сезонный паспорт

У каждой ISO-недели свой паспорт:

| Цель | Награда |
|---|---|
| 3 разных верных диагноза | Сезонный полиглот |
| 3 000 недельных очков | Сезонный охотник |
| 3 верных вердикта в окне PRIME | Бегун PRIME |

Прогресс сбрасывается с новой ISO-неделей. Отдельный **недельный рейтинг** суммирует
очки текущей недели.

### 7.6 Клиффхэнгер

После вердикта показывается, когда откроется следующее запечатанное окно поля. Это
напоминание о реальном `expires_at` раунда, а не тизер выдуманной аномалии.

### 7.7 Эфир Perfect Orbit

При score ≥ 950 можно одним нажатием отправить результат в подписанный hero feed после
включения публичного ретранслятора. Поздний opt-in тоже работает: решил приватно →
включи ретранслятор → эфир. Автоматические события за награды / score ≥ 900 по-прежнему
описаны в §11.

## 8. Созвездие статусов

| Статус | Минимум очков |
|---|---:|
| Звездочёт | 0 |
| Следопыт | 500 |
| Аналитик сигналов | 1 500 |
| Навигатор пустоты | 3 500 |
| Хранитель созвездий | 7 500 |
| Оракул федерации | 15 000 |

Статус — чистая функция накопленных сохранённых очков. Купить его нельзя.

## 9. Реликвии

| Награда | Точное условие |
|---|---|
| Первый контакт | Завершён минимум один проверенный раунд |
| Калиброванный разум | Brier текущего вердикта ≤ 0,08 |
| Глубокое сканирование | Верный ответ после открытия шести улик |
| Чистый вектор | Верный ответ и не менее 800 очков за раунд |
| Инстинкт сигнала | Верно, без улик, уверенность минимум 75% |
| Тройная фиксация | Лучшая серия верных ответов достигает трёх |
| Опытный наблюдатель | Завершено минимум пять проверенных раундов |
| Идеальная орбита | Верный ответ и не менее 950 очков за раунд |
| Двойной замок | Верный диагноз и верный follow-up в одном раунде |
| Хранитель серии | Дневная серия возвратов достигает трёх (один щит на пропуск) |
| Сезонный полиглот | ≥ 3 разных верных диагноза в текущей ISO-неделе |
| Сезонный охотник | ≥ 3000 недельных очков в текущей ISO-неделе |
| Бегун PRIME | ≥ 3 верных вердикта в окне PRIME за текущую ISO-неделю |

Каждая награда хранится один раз на сессию. Это косметические записи, не деньги, токены,
NFT, передаваемая собственность или обещание внешней ценности.

## 10. Рейтинг

Публично видны позывной, проверенные очки, раунды, число правильных ответов, место и
статус. Сортировка: очки, правильные ответы, меньший средний Brier, затем более раннее
время последней игры. Токен сессии и приватные улики не публикуются.

Отдельный **недельный** рейтинг суммирует очки текущей ISO-недели.

## 11. Сообщения о героях

Публичность выключена по умолчанию. После явного opt-in будущий раунд, открывший
новую награду **или** набравший ≥ 900 очков, может создать одно событие. Несколько
наград одного раунда не создают несколько сообщений.

Также доступен one-tap **эфир** для Perfect Orbit / score ≥ 950 после включения
ретранслятора (включая поздний opt-in после приватного сильного вердикта).

Feed подписан по точным каноническим JSON-байтам постоянным Ed25519-ключом provider.
DIOSCURI отвергают устаревший, будущий, изменённый или подписанный другим ключом feed.
Первый poll фиксирует историю без публикации; следующие доставки идемпотентны отдельно
для Discord и X.

## 12. Честная игра

- Не автоматизируйте ответы и не создавайте сессии для накрутки рейтинга.
- Не используйте чужие session tokens.
- Не выдавайте изменённый локальный клиент или БД за публичный deployment.
- Независимая проверка, чтение исходников и self-hosting приветствуются.
- Оператор может исключать автоматический трафик и оскорбительные позывные, но не должен
  менять математику сохранённых вердиктов в пользу игрока.

## 13. Независимая проверка

После вердикта проверьте:

```text
SHA256(round_id:answer_code:answer_salt) == answer_commitment
```

Затем пересчитайте вероятности, Brier, skill, evidence factor, follow-up bonus, множитель
PRIME и округлённый score. О расхождении сообщайте с round ID и state hash, никогда не
прикладывая session token.
